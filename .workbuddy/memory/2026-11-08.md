## 10.0.5：关机守护「撤销」从来没生效过 —— 入口点找错了库

用户要求「守护进程要完全阻止电脑关机」。排查时挖出一个从 10.0.1 就带进来的硬伤：

- P/Invoke 按微软文档把 `AbortSystemShutdown` 声明在 `user32.dll`；
- 本机（Windows 11 26200）`user32.dll` **只导出 `ExitWindowsEx`**，
  `AbortSystemShutdownW` 实际在 **`advapi32.dll`**（用 LoadLibrary +
  GetProcAddress 逐个名字探测确认）；
- 于是每次调用抛 `EntryPointNotFoundException`，被
  `try { … } catch { }` 吞掉 → `ok=false`，读到的是**陈旧的** LastError=2。
  日志里那句「AbortSystemShutdown failed err=2」就是这么来的，看着像系统拒绝，
  实际是入口点都没找到。**前几版所谓「自动取消关机」一次都没成功过**，
  用户看到的「取消」只是 `WM_QUERYENDSESSION` 回 FALSE 把交互式关机拦下。

修法：`UnmanagedFunctionPointer` + `Marshal.GetDelegateForFunctionPointer`，
按 `advapi32 → user32`、`AbortSystemShutdownW → A → 裸名` 逐个解析，解不到就在
日志和设置页明说「只能拦截，撤不掉定时关机」。启动时把解到的入口写进日志。

其余三条同时补上：WndProc 里不再同步撤销（系统正等回话，卡住会被判未响应、
反而给用户「仍要关机」按钮），改只落标记 + 回 FALSE + `BeginInvoke` 排后撤销；
启用 `SeShutdownPrivilege`；400ms 轮询撤销定时关机/更新重启，并终止
`shutdown.exe / PsShutdown / UsoClient`。

**验证方法值得记下来**（`scripts/probe-shutdown-poll.js`）：不靠应用自报，
守护跑着时下发 `shutdown /s /t 1800`，3 秒后外部执行 `shutdown /a` ——
返回 **1116** 说明已无待执行关机（即被守护撤掉了），返回 0 说明还排着队。
定时器给 30 分钟且无论如何都会自己撤一次，脚本怎么跑都不会真关机。

## 10.0.6：用户说「按下关机仍失效」——取证指向测试环境，不是拦截代码

用户报 10.0.5 开了守护还是能关机。取证顺序很重要，记下来：

1. **先找日志而不是先改代码**：守护每次收到关机查询都会写
   `%APPDATA%\chaos-console\shutdown-guard\guard.log`。结果两个正规安装
   目录（`%LOCALAPPDATA%\Programs\ChaosConsole`、`D:/软件与文档/ChaosConsole`）
   都是空壳 —— 用户测 10.0.3 卸载器时真把应用卸了，数据目录一起删了，
   「禁止关机」开关也随之重置。跑的是 `C:/Users/Andy/Downloads/ChaosConsole`
   那份旧版（带 app.asar，10.0.x 已禁用 asar）。所以「失效」至少有一部分
   是拿旧版在测。

2. **机制级验证要能排除「窗体没建起来」和「消息到不了」两种可能**：
   - `scripts/probe-enum-window.js`：枚举全部顶层窗口 → 能枚举到守护的
     hwnd（enum-found=True）；从**外部进程**直接 SendMessageTimeout 发
     `WM_QUERYENDSESSION` → 收回 result=0（是否决），日志同步留痕。
     这条同时排除了「广播被某个挂起窗口中途 abort」的干扰（广播
     SendMessageTimeout 返回 False 只说明系统里存在挂起窗口，不能定论）。
   - `scripts/probe-broadcast.js`：只广播查询消息、不发结束消息，安全。

3. **本轮仍补了三处缝**（防的是「用户环境里恰好走另一条路」）：
   - 除 `WM_QUERYENDSESSION` 外同时处理 `WM_ENDSESSION`，两条都回否决；
   - `ShutdownBlockReasonCreate` 在 OnHandleCreated 里就调并检查返回值，
     理由文字（Windows「阻止关机」界面显示的那句）写进日志，注册失败可见；
   - 设置页显示「拦到过几次 / 最近一次时间 / 走的哪条通道」，
     拦截不再黑盒 —— 用户自己能判断生没生效。

**方法论**：这类「用户说没生效」的问题，先把「应用到底有没有收到广播」
变成可观测事实（日志 + 跨进程探测），再谈改代码。只改代码会反复返工。
